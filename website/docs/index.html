Quickstart

One npm package, Node 22+. Install, then start the daemon by itself — or skip straight to launching an agent:

terminal
npm install -g billion-context     # Node 22+
bili                               # standalone daemon @ http://127.0.0.1:8787

The daemon binds loopback only — nothing is exposed externally. Every instance serves a built-in dashboard:

browser
http://127.0.0.1:8787/__bili/

Connect clients

Three ways to put the proxy between your agent and the model. Pick whichever fits your client:

Native plugin — recommended

Installs a thin plugin straight into the client (the original file is backed up once); deepest integration, with native in-conversation tools. Covers pi · omp · claude · codex · opencode · dsh · kimi · hermes · zcode:

Click any command chip to copy it.

For opencode, bili plugin install opencode --with-mcp also registers its MCP tools.

Launcher — works for any agent

Zero config edits: wraps any CLI agent and injects the proxy + compression state automatically. Each launch brings up a fresh throwaway proxy instance:

terminal
bili pi        # or: bili codex / claude / omp / opencode / hermes /
dsh / codebuddy / qoder / trae / jcode / kimi / gemini / iflow /
qwen / mcode / aider / copilot / amp / goose      (full list: bili --help)

Your own arguments pass straight through: bili pi -r.

Generic proxy — URL prefix routing

Any client that accepts a custom endpoint works out of the box: point its base URL at the prefix below, keeping the original upstream address as the tail:

base url
http://localhost:8787/bili/https://api.openai.com/v1   # example

Replace the trailing https://api.openai.com/v1 with each client's original upstream address — see the table below for exactly where to put it.

Clients that hard-code HTTPS upstreams are handled by an automatic certificate: domains the client reaches are whitelisted on first sight. Need another host? Add it explicitly:

terminal
bili pi --mitm-domain api.foo.com

Commands

bili
Start the standalone proxy daemon (default port 8787).
bili <client>
Bring up a throwaway proxy + launch the chosen client against it — no config edits.
bili plugin install|list|update|remove
Manage the per-client plugins and their update lanes.
bili test pi
Non-polluting smoke test through the proxy.
bili export [session] [--full]
List sessions, or export one as a Markdown handoff document (--full restores original messages).
bili doctor
Audit every install lane: versions, owners, running proxies (read-only).
bili update
Check for and install a newer version now.
/acp
Live context panel inside your agent — includes this session's web-dashboard link.
/acp-cache
Token economics report for the session: new content vs cache hits vs compression repay.

Configuration

Everything lives in one JSON file, created automatically on first run:

~/.config/billion-context/billion-context.json
{
  "compress": {
    "maxContextLimit": "75%",
    "promptPack": "lean",
    "ccr": { "enabled": true }
  },
  "providers": {
    "https://api.anthropic.com": {
      "models": { "claude-sonnet-4-6": { "context": 200000 } }
    }
  }
}

Environment overrides (win over the file):

env
ACP_PORT=8787                    # listen port
ACP_HOST=127.0.0.1               # bind address
ACP_UPSTREAM=https://api.anthropic.com # fallback upstream base URL
ACP_PASSTHROUGH=1                # force passthrough on (wins over file)
ACP_PROVIDERS=/path/to/routes.json # external routes file (beats inline)
BILI_CONFIG_FILE=~/.config/...   # override the config file path
BILI_SESSIONS_DIR=~/.local/share/... # where session records are stored
BILI_UPSTREAM_PROXY=http://host:port   # outbound egress proxy
ACP_MODEL_CONTEXT_LIMIT=200000   # global context window override
BILI_MITM_DOMAINS=api.foo.com    # add MITM whitelist domains
BILI_REPLAY_RETRY_MAX=3          # transport-failure replays
BILI_SESSION_GC=1                # enable session garbage collection
BILI_IMAGE_TOKEN_CAP=8192        # per-image token budget
BILI_SUBAGENT_SPLIT=0            # disable subagent session split
BILI_FORK_ADOPTION=1             # adopt anonymous forks into parent session
ACP_LOG_FILE=/path/to/bili.log   # explicit log path
ACP_COMPRESS_TOOL=0              # disable the injected compress tool
ACP_COMPRESS_NUDGE=0             # disable growth nudges

How compression works

The same four mechanisms as the front page, condensed:

  • Folded, not rewritten When history outgrows its budget, only the newly consumed slice is folded into a compact summary block — once, per block. The window oscillates in a bounded band instead of growing without limit: production sessions run months at ten-thousand-plus calls. Any block decompresses back to full text when you need the detail.
  • The provider's cache stays warm A fold deactivates old ranges without touching the front of the conversation, so the prompt-cache prefix survives turn after turn — 94.2% of active input was served from cache in the study. Rewrite-style compaction invalidates the whole prefix and re-bills it. This does not.
  • The model decides what to forget A versioned compression doctrine lives in the system prompt; a growth-gated nudge says when folding pays off. The agent judges what the task still needs, may refuse, and compresses between steps — never mid-step.
  • Every token is accounted Each request is sampled into a per-session ledger — new content, cache reads, compression repay, TTL expiry — plotted in percentage points on a trajectory chart. Audit real savings with /acp in the terminal or the built-in web UI at /__bili/.

The full treatment, with numbers: read the preprint.

Web UI

Access: once the daemon is up, open http://127.0.0.1:8787/__bili/ in a browser (change the port if you set ACP_PORT; it binds loopback only). Or just type /acp in your agent — the panel footer carries a direct link to the current session.

Every running instance serves a built-in dashboard at /__bili/:

  • Overview — total sessions and requests, gross and net savings, global hit rate with miss breakdown, protocol distribution.
  • Sessions — usage cards, context trajectory chart, cache economics with fold detail, compression blocks, and the Markdown handoff document (copy or download).
  • Configuration — view and edit the JSON config; changes apply immediately.
  • Connect — per-instance wiring guide with copyable commands.
  • Logs — live tail of the daemon log, filterable by session id or keyword, downloadable as plain text.

Privacy

billion-context runs only on your machine and binds loopback by default. It forwards model traffic — OAuth tokens pass through untouched, unauthenticated probes aside — and uploads nothing.

Session records stay local (~/.local/share/billion-context/sessions); the log sits beside the state dir. Export any session with bili export, delete files whenever you like.

FAQ

Which Node version?

Node 22 or newer — required by the npm package.

Does it work on Windows?

Recommended: WSL2. Inside WSL everything uses 127.0.0.1 as usual; a Windows-side client should reach the proxy via the WSL host IP, or simply run the client inside WSL too.

Do I pay for the proxy itself?

No — it's free and open source (MIT plus an attribution clause). Token savings come from smaller contexts and your provider's prompt caching; the economics panel shows the real per-session numbers.

How do I upgrade?

Run bili update (or reinstall via npm). Use bili doctor before and after to audit every install lane.

I can’t reach the dashboard?

Check the daemon is running (bili doctor) and the port isn’t changed (default 8787). The dashboard binds 127.0.0.1 only — from another machine or phone you need an SSH port-forward or an explicit ACP_HOST setting.
